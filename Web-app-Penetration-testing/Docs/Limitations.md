# Vulnerability Management Engineering Limitations

This document captures the boundaries, constraints, and systemic conditions under which the Week 20 portfolio project was conducted for Velora Commerce GmbH.

*   **Single Asset Constraint:** The lifecycle assessment was executed against exactly **one local laboratory virtual machine** (`LAB-UBU-01`). The resulting operational metrics cannot be extrapolated to predict the scale or behavior of Velora's wider multi-server target production environment.
*   **Constrained Evaluation Window:** The project was completed over a **single, brief testing window**. This snapshot fails to capture long-term enterprise trends, systemic patch drift, or programmatic configuration volatility.
*   **Licensing Capabilities Bounds:** The project utilized the **Tenable Nessus Essentials license profile**, which enforces strict limits (such as a 5-IP scanning ceiling). Under this version profile, professional XML/CSV report data exports are natively restricted. Results had to be manually extracted and transcribed into project summary targets.
*   **Data Retention Risks:** Due to free-tier structural constraints, scan historical logs and raw scanner metrics **may disappear from the scanner console after license expiration**, mandating aggressive, point-in-time snapshot transcription to maintain audit visibility.
*   **Least-Privilege Auditing Bounds:** The SSH service configuration utilized a **strictly unprivileged auditing identity** (`nessus-audit`). Without administrative root/sudo privileges, the scanner could not inspect restricted file repositories, query low-level kernel configurations, or audit system configurations.
*   **Plugin-Feed Asynchrony:** Automated scanning results rely on the active vendor plugin feed signature set. Any discrepancy or **plugin-feed version alteration** occurring between baseline testing and remediation re-checks can introduce or remove vulnerability flags entirely independently of actual remediation efforts.
*   **Stable Upstream Backports Mismatch:** Ubuntu distributions heavily utilize **upstream security backports**, where security fixes are applied directly into existing package sub-versions without incrementing the primary version number. Standard version-based scanning indicators can report misleading vulnerabilities that are technically patched.
*   **Lab Network Isolation Mismatch:** The lab environment runs inside a local **NAT-segmented virtual switch hypervisor namespace**. This network architecture differs fundamentally from the threat modeling parameters of an internet-facing production server exposed to distributed reconnaissance assets.
*   **Exploitation Omission Rule:** Security analysts conducted **passive configuration validation only**. Active operational exploitation payloads or proof-of-concept exploits were explicitly withheld to defend system uptime and abide by authorized rules of engagement.
*   **Apple Silicon Architecture Exclusions:** The host environment (MacBook M1) restricts the deployment of enterprise containerized web application fuzzing engines natively. Deep interactive application scanning was omitted from this testing matrix.
*   **Generalization Boundary:** The engineering outcomes, remediation codes, and performance data points generated here **cannot be generalized to all Velora corporate networks** or standard Ubuntu system branches. They represent localized validation matrices only.
